## 段階E1（worktree `feat/question-wrap-join`）: 1 と 4

1. 折り返しのつなぎ直し: 画面の質問の判断待ちの題名（質問文・許可確認のコマンド）と、同じつなぎ直しを使う所すべて。英文の普通の折り返しの空白は今までどおり戻す。上の例と、英文・日本語・パス・行より長い語のテストを足す。本物の Claude Code で、狭いペインに長いファイル名や日本語の質問を出させて、題名に余計な空白が入らないことを確かめる。
2. 保存マシンの判断待ちへの回答: `gtx decision watch --all-machines` で見える保存マシンの判断待ちに、手元から `gtx decision answer`（とプラグインが使う API）で答えた時、その保存マシンの判断待ちが answered になり、画面の質問ならキーがそのマシンの pane に届くかを、保存マシンをもう1つの gtx server（ssh で localhost か mini）にして確かめる。届かなければ原因を書いて直す。既に届くなら、その証拠を書く。

## 段階E2（worktree `feat/tab-status`）: 2 と 3

1. タブの状態アイコン: タブバーの各タブ名の先頭に、スペースのサイドバーと同じ記号・色・集計の決まり（そのタブのペインのうち、質問待ち＞実行中＞完了…の優先、実行中の回転表示も同じ）でアイコンを出す。エージェントのいないタブ、判断待ちの注意表示（blocked に重なる表示）も同じ決まりに従う。保存マシンのタブ（endpoint の画面）も同じ表示にする。タブ名を変えた時・幅が狭い時の表示が崩れないこと（アイコンは名前の前に1つ、名前の省略はアイコンを残して名前側を詰める）。表示だけで、タブ名そのもの（API の label）は変えない。
2. タブのドラッグ＆ドロップ: gtx には既に `internal/tui/tab_drag.go` がある。本物の端末のマウス操作で、サーバー方式・`--no-session`・保存マシンのタブで並べ替えができ、フォーカスが変わらず、再起動後も順番が残ることを確かめる。足りなければ直す。
