# moonterrace 第1段階の追加: マウスだけで全操作できるようにする

この文書は実装担当（Devin SWE-2 High）への指示書です。`docs/PLAN.md` の決まりはすべてそのまま有効です
（設計方針・依存・やってはいけないこと）。この文書はその上に「マウス操作」を足します。

## 0. なぜ

店長が触って「マウスネイティブじゃない。マウスですべてできる必要がある」と判断しました。
herdr は「マウスを主に使う TUI」です（herdr fork `AGENTS.md`: "Herdr is a mouse-first TUI"）。
今の mt はサイドバーのクリックとペインのクリックしか無く、分割・閉じる・ワークスペース作成・終了などは
`Ctrl-b` のキーでしかできません。

## 1. 完了の条件（ひとことで）

**PLAN.md 5.8 の表にあるキー操作が、すべてマウスだけでもできること。** さらに、マウスで端末を掴んだことで
失われる「ドラッグで文字を選んでコピー」と「ホイールで過去の出力を見る」も mt 側で用意すること。
キー操作は今のまま残す（消さない・変えない）。

## 2. herdr fork の参考箇所（読むだけ）

- `~/src/github.com/kazuph/herdr/SPEC.md` の「pane menuのレイアウト操作」「Workspaceメニューとサイドバー操作」
  「サイドバー空白メニューと危険操作確認」「pane描画・resize・mouse routingの微細契約」の節
- `src/app/input/mouse.rs`（右クリックメニュー、仕切り線のドラッグ、ホイールの振り分け）
- `src/ui/sidebar.rs` の `collapsed_sidebar_toggle_rect` / `expanded_sidebar_toggle_rect`（`«` `»` の位置）と `[menu]` `[new]` の描画

## 3. 作るもの

### 3.1 メニュー（共通部品）

- クリック位置に出るポップアップ。枠付き、項目は1行1つ、`--` は区切り線。
- マウスを乗せた項目を反転表示（ホバー）。項目をクリックで実行してメニューを閉じる。
- メニューの外をクリック、または `Esc` で何もせず閉じる。キーボードの上下と `Enter` でも選べる。
- 画面の端からはみ出す場合は、収まる位置にずらす。
- メニューが開いている間のマウス・キー入力はメニューが受け取り、ペインへは送らない。
- 状態（開いているメニューの種類・位置・ホバー位置）は **TUI 側だけ** に置く（PLAN.md 1章「サーバーとクライアントの境界」。
  `model` には入れない）。メニュー項目を選んだ結果は既存の `Command` を発行する。

### 3.2 確認ダイアログ（共通部品）

- 画面中央、赤い枠。タイトル1行、説明1行、ボタン `[ cancel  esc ]` と赤い `[ <動詞>  ↵ ]`。
- 確認ボタンのクリックか `Enter` で実行、cancel・枠の外のクリック・`Esc` で取り消し。
- 使う場面: ワークスペースを閉じる（中のシェルとエージェントが全部終わるため）、mt を終了する。
  - ワークスペースを閉じる: タイトル `Close workspace?`、説明 `Closes <名前> and all of its panes.`、ボタン `close`
  - 終了: タイトル `Quit moonterrace?`、説明 `Stops all panes in every workspace.`、ボタン `quit`
- キーの `Ctrl-b Shift-d` と `Ctrl-b q` も、この確認ダイアログを出すように変える（マウスとキーで挙動をそろえる）。

### 3.3 ペインの右クリックメニュー

ペインの中身か枠を右クリック → その位置にメニュー。対象ペインにフォーカスを移してから開く。項目と順番:

```
Split vertical        （左右に分割 = prefix v）
Split horizontal      （上下に分割 = prefix -）
--
Close pane            （= prefix x）
```

- ペイン内のアプリがマウスを要求している（`mouse_tracking()` が true）ときは、右クリックをアプリへ送り、メニューは出さない。
  その場合でも **ペインの枠（罫線）の右クリック** ではメニューを出す（アプリを使っていても操作できる逃げ道）。

### 3.4 仕切り線のドラッグで大きさを変える

- 分割の境目の罫線を左ボタンで押してドラッグすると、その分割の比率が変わる（左右分割なら横方向、上下なら縦方向）。
- 比率は 0.1〜0.9 に制限。離したら確定。ドラッグ中もペインの大きさを追従させ、PTY と端末エンジンをリサイズする。
- `layout` に「この座標の境目はどの分割か」を返す純粋関数と、「分割の比率を変える」純粋関数を足し、テストする。

### 3.5 サイドバー

- **ワークスペース行のクリック**: 表示中でない行 → そのワークスペースへ切り替える（今のまま）。
  **表示中の行** → その位置にワークスペースメニュー:
  ```
  New workspace
  --
  Close workspace…     （確認ダイアログへ）
  ```
- **エージェント行のクリック**: そのワークスペースへ切り替え、そのペインにフォーカス（今のまま）。
- **下端の操作行（フッター）**: サイドバーの最下段の行に、左 `[menu]`、右 `[new]` を出す。
  - `[new]` クリック → 新しいワークスペース（= prefix Shift-n）
  - `[menu]` クリック → 全体メニュー:
    ```
    New workspace
    Next workspace
    Previous workspace
    --
    Hide sidebar
    --
    Quit moonterrace…   （確認ダイアログへ）
    ```
- **折りたたみボタン**: 開いているサイドバーの右下に `«`。クリックで折りたたむ（= prefix b）。
- **折りたたみ状態**（今は幅0で消えている → 変える）: 幅 3 列の細いサイドバーを残す。
  - 各ワークスペースを1行で、状態記号だけ表示（▲ ● ◐ ○ ·。表示中のワークスペースは反転）。クリックでそのワークスペースへ。
  - 最下段の中央に `»`。クリックで開く。
- サイドバーの行が画面に収まらないときは、ホイールで上下にスクロールできる。

### 3.6 ホイール

マウスがある場所で振り分ける（herdr の `wheel_routing_*` のテストと同じ考え方）:

1. ペインの上で、ペイン内のアプリがマウスを要求している → アプリへホイールを送る
2. ペインの上で、アプリが代替画面（全画面アプリ。vim や less など）を使っていてマウスを要求していない → 上下矢印キーを3回分送る
3. ペインの上で、それ以外 → そのペインの過去の出力（スクロールバック）を3行ずつ上下に表示する。
   スクロール中はペインの枠の上辺右側に ` ↑<行数> ` を出す。キー入力をそのペインへ送ったとき、
   または一番下まで戻したときに、最新の表示へ戻る。新しい出力が来てもスクロール位置は保つ。
4. サイドバーの上 → サイドバーのスクロール（3.5）

### 3.7 ドラッグで文字を選んでコピー

- ペインの中を左ボタンでドラッグ → 選んだ範囲を反転表示。離したら選んだ文字を **OSC 52**（端末へのクリップボード書き込み命令）で
  外側の端末へ送り、範囲の表示を消す。ステータス行に ` copied <文字数> chars ` を2秒出す。
- 範囲の行末の空白は削る。全角文字は2列分を1文字として扱う。スクロール中なら表示中の位置で選ぶ。
- ペイン内のアプリがマウスを要求しているときは、ドラッグをアプリへ送り、選択はしない（herdr と同じ）。
- 端末エンジンの選択機能（`StreamTerminal::selection`、`Formatter` の `selection` 指定）が使えるか、まず `pkg.generated.mbti` で確かめる。
- **店長のクリップボードを読まない**（貼り付けは扱わない。書き込みは店長がドラッグで選んだときだけ）。

### 3.8 ステータス行

- 右寄せの状態件数の左に、クリックできる ` [split │] [split ─] [close] ` を出す（フォーカス中ペインに対する操作）。
  幅が足りなければ出さない（クリック範囲も無効）。

## 4. テスト

- 純粋部分（layout の境目判定と比率変更、メニューの位置計算とはみ出し補正、クリック位置からの対象判定、ホイールの振り分け）は単体テスト。
- render のスナップショットテスト: 開いたメニュー、確認ダイアログ、折りたたみサイドバー、`[menu]` `[new]` `«`、スクロール中の ` ↑<行数> `、選択範囲の反転。
- `tests/e2e` に、実 PTY で mt を起動し **SGR マウス入力のバイト列を送って** 次を確かめるテストを足す:
  右クリック→`Split vertical` で2枚になる、仕切り線ドラッグで幅が変わる、`[new]` でワークスペースが2つになる、
  `[menu]`→`Quit moonterrace…`→確認ボタンで終了コード0。

## 5. 動作確認（本人が必ず行う）

PLAN.md 7章と同じく herdr の検証用ペインで mt を動かす。マウスは `herdr pane send-text` で SGR マウスのバイト列
（例: 左押し `\e[<0;<列>;<行>M`、離す `\e[<0;<列>;<行>m`、右押し `\e[<2;…M`、ホイール上 `\e[<64;…M`）を送り、
`herdr pane read` で画面を読む。キーボードを一切使わずに次を通しで行い、各段階の画面を `.artifacts/mouse/` に保存する:

1. `[new]` でワークスペースを作る → サイドバーの行クリックで切り替える
2. ペインを右クリック → `Split vertical`、もう一度 → `Split horizontal`
3. 仕切り線をドラッグして幅を変える
4. `seq 1 200` の出力をホイールでさかのぼる → 一番下へ戻す
5. 文字をドラッグで選ぶ（OSC 52 が出ていることは `herdr pane read --format ansi` か e2e テストで確認）
6. 右クリック → `Close pane`
7. `«` で折りたたみ → 細いサイドバーの記号クリックでワークスペース切替 → `»` で開く
8. 表示中のワークスペース行クリック → `Close workspace…` → 確認
9. `[menu]` → `Quit moonterrace…` → 確認で終了

## 6. やらないこと

計画にないメニュー項目（Zoom、Move to split、Equalize、Rotate、Rename、エージェント起動、設定、タブ）は作らない。
必要そうなら RESULT.md の発見事項に書くだけ。
